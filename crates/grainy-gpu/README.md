# grainy-gpu

Port of `luma/native_gpu.py` to wgpu 30.0.2 / WGSL. The reference is the Rust CPU tone/colour/detail/effects chain.
No Python, OpenCV, photo library, settings file or native oracle DLL is used at runtime.

The app now uses the feature-gated engine integration described in [PREVIEW_REPORT.md](PREVIEW_REPORT.md),
including resident preview caching, exact CPU fallbacks, CPU masks before clipping, and a GPU settings switch.

```rust,no_run
use grainy_gpu::{Gpu, Resident};
# fn example(image: &grainy_core::Image) -> grainy_gpu::Result<()> {
let Some(gpu) = Gpu::new() else { return Ok(()); }; // choose the CPU renderer
let mut settings = grainy_core::defaults();       // API expects normalized settings
let mut resident = Resident::new(&gpu, image)?;
if let Some(frame) = gpu.develop_resident(&mut resident, &settings, 1.0)? {
    let pixels = gpu.readback(&frame)?;
    // Display/save `pixels`, or retain `frame` for subsequent GPU processing.
}
settings.set("saturation", 20.0);
let next = gpu.develop_resident(&mut resident, &settings, 1.0)?;
// Source upload and tone are reused. `resident.runs()` exposes the actual stage counts.
# Ok(())
# }
```

`Gpu::develop(&Image, &Settings, pixel_scale)` is the upload/develop/readback convenience API. `Ok(None)` requests
CPU processing for unsupported settings. `Err` reports bad input, a resource limit or a failed/lost device.
`Gpu::new()` logs initialization failure and returns `None`; `Gpu::with_adapter` preserves diagnostics and selects
hardware or the forced software adapter. A lost context is never reused; create another `Gpu` and reupload.

`tone`, `color`, `detail`, `tone_frame`, `color_frame`, `detail_frame` and `grain_clip` expose individual stages.
Tone accepts scene-linear pixels and produces encoded pixels. Colour/detail operate on encoded pixels. Detail
does not include grain or the final clip; `develop` includes both. The input of `develop` is already past geometry,
negative conversion, RAW processing and colour-space conversion, just like the oracle native chain.

`Frame` owns an interleaved RGB float32 storage buffer, 12 bytes/pixel. This preserves float32 precision and avoids
RGBA16 quantization and the extra channel of RGBA32. Upload validates finite, nonempty RGB, accepts strided ndarrays,
checks adapter size/dispatch limits and does not panic on invalid inputs. Readback maps a separate staging buffer
with a bounded wait. Frames carry context identity and cannot be passed to another GPU. The crate contains no unsafe.

Output and readback buffers are pooled per device and exact byte size. Output buffers return only after the last
`Frame` clone is dropped; retaining an earlier slider result preserves its pixels. All dispatches use the same
queue, so reusing a dropped intermediate requires no extra synchronization. Staging buffers return only after a
successful readback and unmap; concurrent readbacks use separate leases. Idle output buffers are capped at 1 GiB
and 16 buffers, idle staging at 512 MiB and 2 buffers, with oldest-first eviction. Oversized buffers are not cached.
Live frames do not count toward these idle limits. Source uploads and small parameter buffers are not pooled.

Resident source/tone/colour/detail/final frames and the grain field remain on the device. Structural settings keys
invalidate only downstream stages. Highlights/Shadows reuse the CPU `grainy_tone::ToneBase`; changing exposure,
WB or lens lift refreshes it. The grain field is generated by `grainy_effects::settings_grain`, as in the oracle,
and uploads once per grain key. `replace` explicitly replaces source geometry and clears all dependent slots.

Colour filters and all detail pixel filters are WGSL. Luminance denoising has a deliberate host boundary: legacy
bilateral reads back Lab extrema for the OpenCV LUT; wavelet reads back three residual/guide frames for numpy's
float64 noise-profile reductions. No CPU pixel filtering occurs there. `detail_tools_on_gpu` reports this boundary.
Colour denoising needs no readback. Supplying an internal `wavelet_profiles` 3x8 table avoids wavelet reductions.
This is a correctness-first implementation; a small GPU reduction buffer can replace the full-frame statistics
readbacks in future. The performance example disables noise reduction and local tone maps.

Fallbacks and resource limits:

- Tone: active known film look, DRT, malformed/nonmonotonic nonidentity curve, more than 4096 curve points.
  Unknown film names and zero-strength films are inactive, as in the oracle. The individual tone stage supports HDR.
- Colour: HDR, enabled photo filter, malformed curves/point colours or group dimensions, over 4096 total active curve
  points or 256 active point colours. Invalid/nonfinite camera matrices are ignored, as in the oracle.
- Detail/whole chain: HDR, pixel scale above 32, sharpen sigma above 256, or an image whose clarity sigma exceeds 256.
  Zero/nonfinite pixel scale is an error. These loop bounds avoid unbounded dispatches on invalid settings.
- Local adjustments, optical warps and rotation are outside this brief. Film rendering, DRT and photo filters use
  the CPU fallback. Display integration, image decode/encode and the whole application renderer are outside this crate.

Important parity choices:

- Preserve exposure then white balance, the rational shoulder, process 1/2 versus process 3, and the HDR curve extension.
- Use float32 GPU interpolation for the CPU's float64 local-map interpolation, with measured rounding tolerances.
- Preserve HLS SIMD versus scalar-tail arithmetic, float32 `allclose` identity tests, v1 point-colour whole-frame
  roundtrips and v2 zero-weight preservation. Monochrome belongs to detail; photo filters trigger fallback.
- Duplicate curve abscissae select the last value as the CPU's numpy interpolation does. The old HLSL shader's
  first-match interpolation differs at exact duplicate knots; the explicit CPU reference takes precedence here.
- Preserve `BORDER_REFLECT_101`, the 1-pixel border case, banker rounding of filter radii, deterministic numpy grain,
  luminance sharpening for detail versions 2/3, and colour-before-luminance noise reduction.
- Specialize detail shader stages at pipeline compilation. Explicit `.y`/`.z` writes avoid an FXC compiler crash
  with a dynamic vector assignment. This needs neither DXC redistribution nor extra native code.

Verification commands (from the worktree root; add the user's Cargo bin directory to PATH):

```text
"$GRAINY_ORACLE/.venv/Scripts/python.exe" -B tools/golden/gen_gpu.py
cargo fmt --check
cargo clippy -p grainy-gpu --all-targets -- -D warnings
cargo test -p grainy-gpu -- --nocapture --test-threads=1
cargo run -p grainy-gpu --release --example bench
```

The generator disables bytecode before importing the read-only oracle. `golden/gpu` holds a compact settings
matrix and case index, one nonstandard hue wheel, and nine oracle Gaussian kernels (13 files, 156,552 bytes).
It stores no expected image pixels. Tests use `grainy-testkit` to load metadata and standard inputs, compute
expected images with `grainy_tone`, `grainy_colorgrade`, `grainy_detail` and `grainy_effects`, and compare full frames
on both hardware and WARP. The chain uses those CPU stages in engine order, including grain once and the final
clip, without output colour conversion. Large detail frames are no longer subsampled. A test enforces the 3 MB
fixture limit. Regeneration reproduces the committed bytes.

Tests skip clearly only when there is no adapter, and fail initialization/shader errors when an adapter exists.
An empty-backend test exercises the no-adapter result for both policies. See [REPORT.md](REPORT.md) for measured
errors, CPU-reference quirks and the before/after benchmark. Logs are local diagnostics, not committed fixtures.
